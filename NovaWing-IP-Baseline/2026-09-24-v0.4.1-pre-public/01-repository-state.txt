    fix(desktop): persist Windows updater feed in packaged tree

    The packaged Windows app carried no app-update.yml at all. electron-builder
    writes it from an afterPack hook, and that hook runs for neither of this
    build's targets: `dir` is not a distributable target, and the prepackaged
    NSIS build returns from doPack before the hook. A shipped Windows app would
    therefore have had no feed to read.

    The packaging adapter now writes the file itself, at the point where the
    unpacked tree is complete and before it is audited, so the packaged smoke
    validates a tree that already carries the feed and the installer re-packs
    that same tree.

    The file also joins the packaged identity. Without that, a feed swapped after
    the smoke ran would hash identically and the installer could be built from a
    tree no smoke ever saw. The installer phase verifies the feed rather than
    writing it, so a missing or altered feed fails closed instead of being
    repaired on the way past.

    The document itself is assembled without a YAML library: every value is a
    fixed identifier from the single feed source, and each is checked against a
    plain-scalar pattern before it is written, so a value that would need
    escaping fails the build instead of producing a malformed document.
