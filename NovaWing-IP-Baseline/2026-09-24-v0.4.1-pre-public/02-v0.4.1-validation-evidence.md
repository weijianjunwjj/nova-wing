### 3.1 The macOS notification run is normalised, not silently passed

This must be read with the limitation attached.

The macOS `notification-smoke` run reports `report.result: "FAIL"` **and**
`nativeDelivery.gate: "NEEDS_SIGNED_VALIDATION"`. The harness in
`scripts/desktop-smoke.mjs` normalises the outer run result to `NEEDS_SIGNED_VALIDATION`
because the bundle is not signed for distribution, and the smoke gate accepts either `PASS`
or `NEEDS_SIGNED_VALIDATION`:

```text
scripts/desktop-smoke.mjs:305-307
  result.result = result.runs.length === (packagedRoot ? 6 : 4) &&
    result.runs.every((run) => run.result === 'PASS' || run.result === 'NEEDS_SIGNED_VALIDATION') && …
```

So `packageSmokeResult: PASS` is correct **only together with** the documented limitation:

```text
Developer ID signing:  NOT AVAILABLE
Notarization:          NOT PERFORMED
Native Notification:   NEEDS_SIGNED_VALIDATION
Gatekeeper:            not claimed
```

Native notification delivery was **not** validated on the macOS artifacts, and is not claimed.
The remaining 15 notification checks are marked `Not run` in that artifact. This is the same
limitation already disclosed in the release notes.
