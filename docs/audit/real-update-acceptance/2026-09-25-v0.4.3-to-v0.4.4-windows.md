## Telemetry limitation

```text
TELEMETRY_LIMITATION = OBSERVABILITY_GAP
E2E_FAILURE = NO
```

The updater observation fields `installRequests` and `installAuthorizations` are not automatically
emitted after `requestRestartAndInstall()` advances into the shutdown/install path. The last
`updater-state` event is the pre-request `READY` snapshot, so this `events.jsonl` does not directly
record the post-click values of those two counters.

That absence must not be interpreted as zero install requests or zero authorizations. The
candidate-bound user action is evidenced indirectly but deterministically by the subsequent
`strict-quit-drained` event and the new packaged `0.4.4` startup from the same installation and
userData paths. This is an observability gap, not a failure of this real auto-update E2E.
